# 慧眼的三个零件

唯一业务基准是已经使用的普通慧眼。当前保留合同、证据、状态记忆、去重、音频交付及今天新增的准备缓存和4秒内有效结果接回。换模型只适配接口和格式，不另造业务规则。

| 层 | 职责 | 当前适配 |
| --- | --- | --- |
| 播报层 | 原Live合同交互、普通问答及已审核结果发声 | Google或阿里，沿原连接和音频实现 |
| 应用层 | 完整合同的画面复核、事实整理、应用状态处理 | Google或阿里 |
| 筛图层 | 持续检查当前图 | 云端跟随应用层；端侧使用本地模型 |

组装定义只有一份：`shared/huiyan-model-layers.js`。普通云端检查、直连准备缓存以及原生本地复核都引用它。当前本地预设是本地Y/N、阿里3.7复核整理、所选Google或阿里Live播报；本地否定时跳过云端审核，命中时不再经过Google Lite或prepare。模型权重、音频链、原生权限和时间预算不由组装模块修改。

`cloudPlan(speechProvider, applicationProvider)`让云端筛图跟随应用层；`localPlan(speechProvider, localModel)`使用当前已验证的阿里应用层。`resolve`可描述其他已适配组合；新供应商先实现自己的应用内接口，再用`registerProvider`注册。接口仍须遵守现有权限和部署配置。组装定义不代表所有供应商组合都已配置或验收，也不会自动启用付费路线。

播报保留普通慧眼原有的[SAY]正文逐字播报、不读标记与流程话术，并共用一条结果规则：回答合同关心的结果，保留本次正文已有的位置、方位和状态，不用合同确认句或固定模板覆盖正文，不编造位置或距离。Google与阿里结果播报引用同一规则。阿里合同决策轮的暂存与单次确认机制原样保留，避免先念问题、建立合同后又念一次。此规则是网页更新，build106原生源码归档保持其构建时的准确内容。

改公共定义后运行`node tools/sync-model-layers.cjs`生成两端静态副本，再运行`node tools/test-model-layers.cjs`。测试验证组合、替换适配器、共同规则等价和副本一致；`tools/test-reminder-grace.cjs`与`tools/test-prepare-cache.cjs`保留时序回归。原生源码包也保留同一shared定义。教学没有迁入本模块，导航保持冻结。
